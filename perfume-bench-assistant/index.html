PerfumeBench Assistant

Asistente físico de banco para perfumería: voz manos libres, cálculos, inventario, fórmulas, revisiones y notas de laboratorio, con ESP32-S3 como terminal y un backend conectado a OpenAI Realtime.

Objetivo y alcance

Qué debe lograr

  • Permitir conversación natural mientras se pesa o formula.
  • Consultar inventario, diluciones, fórmulas y revisiones sin tocar el celular.
  • Calcular porcentajes, escalados y adiciones de materias primas.
  • Guardar notas experimentales por voz y mantener trazabilidad.
  • Mostrar datos críticos en una pantalla pequeña.
  • Conservar estado entre sesiones mediante una memoria de laboratorio estructurada.

Qué NO debe ser en v1

  • Un sustituto completo de la app de ChatGPT.
  • Un sistema que guarde la API key de OpenAI en firmware.
  • Un instrumento de medición química.
  • Un sistema que invente límites regulatorios o IFRA.
  • Un dispositivo siempre escuchando desde el primer día.

Principio de diseño

El ESP32 es el terminal. El cerebro vive en el backend.

El dispositivo captura y reproduce audio, muestra estado y ejecuta una máquina de estados simple. El backend concentra autenticación, conexión a OpenAI, herramientas, memoria, control de versiones y reglas del dominio.

Capa 1 · Device

Audio, botones, LEDs, pantalla, Wi‑Fi, buffer y reconexión.

Capa 2 · Gateway

Autentica dispositivo, mantiene WebSocket, sesión Realtime, tool calls y streaming.

Capa 3 · Lab Memory

Inventario, diluciones, fórmulas, versiones, lotes, evaluaciones y preferencias del laboratorio.

Estado conversacional. La API Conversations permite conservar una conversación con un ID durable entre sesiones, dispositivos o procesos. La memoria operativa del laboratorio, sin embargo, debe quedar además en tablas/objetos propios para que sea auditable y no dependa sólo del contexto del modelo.

Backend / Device Gateway

Runtime

Node.js + TypeScript. Despliegue inicial en Vercel Functions con WebSockets; si aparecen límites de duración o latencia, migrar sólo el gateway a Cloud Run sin tocar el resto.

Responsabilidades

  • Autenticación de dispositivo.
  • Sesión Realtime.
  • Traducción de eventos.
  • Tool calling.
  • Persistencia.
  • Observabilidad.
  • Rate limiting.

Flujo de una interacción

1. ESP32 abre WSS /api/device
2. Gateway valida device_id + device_token
3. PTT → audio PCM empieza a fluir
4. Gateway lo envía a OpenAI Realtime
5. El modelo:
   a) responde por audio, o
   b) pide una tool
6. Gateway ejecuta tool contra memoria de laboratorio
7. Resultado vuelve al modelo
8. Modelo produce respuesta hablada
9. Gateway transmite audio + tarjeta UI al ESP32
10. Se guarda transcript + acciones + revisión de fórmula si corresponde

Regla UX: cualquier modificación de fórmula debe ser “propuesta → lectura del resultado → confirmación → commit”. Consultas y cálculos no requieren confirmación.

Prompt operativo base

Sos PerfumeBench, un asistente de laboratorio especializado en perfumería.

PRIORIDADES:
1. Exactitud de masa, concentración y versión.
2. Respuestas habladas breves.
3. Nunca inventes inventario, pureza o concentración.
4. Antes de escribir/modificar una fórmula, mostrás el cálculo y pedís confirmación.
5. Registrás toda modificación como nueva revisión; nunca sobrescribís una revisión histórica.
6. Si una materia prima tiene una dilución de trabajo, distinguís siempre "material puro" de "solución".
7. Expresás masas en gramos con tres decimales salvo que el usuario pida otra precisión.
8. Para límites regulatorios/IFRA, usás documentos cargados y citás la fuente; si no hay fuente, decís que no está verificado.
9. Priorizás información observable y no presentás una hipótesis olfativa como dato químico.
10. En voz, das primero el número o acción importante y luego la explicación.

CONTEXTO:
- El usuario trabaja con fórmulas por peso.
- Inventario y diluciones son fuentes de verdad externas al modelo.
- Los cambios de fórmula requieren confirmación explícita.

Seguridad, privacidad y confiabilidad

Secretos

  • API key de OpenAI sólo en servidor.
  • Token individual por dispositivo.
  • Guardar únicamente hashes de tokens.
  • Rotación de credenciales.
  • Variables de entorno para secretos.

Datos

  • Audio efímero por defecto.
  • Transcript opcional.
  • Audit log para escrituras.
  • Backups de fórmulas.
  • Export JSON/CSV.

Química

  • Separar cálculo matemático de recomendación de seguridad.
  • No inferir límites IFRA.
  • Mostrar pureza/dilución en pantalla.
  • Alertar cuando falta unidad o concentración.

Robustez

  • Watchdog.
  • Reconexión exponencial.
  • Buffer limitado.
  • CRC/secuencia de chunks.
  • OTA con rollback.
No colocar una API key larga dentro de secrets.h del firmware definitivo. Aunque algunos demos lo hacen, para este proyecto el dispositivo sólo debe autenticarse contra nuestro gateway.

Roadmap de implementación

Fase 0 — Spike de audio

ESP32 + INMP441 + MAX98357A. Grabar/reproducir audio local. Medir ruido y niveles.

Fase 1 — MVP Push-to-Talk

PTT → gateway → OpenAI Realtime → respuesta por parlante. Sin memoria persistente.

Fase 2 — Inventario + cálculos

Agregar herramientas de consulta y cálculo de diluciones/escalados.

Fase 3 — Fórmulas versionadas

Propuesta, confirmación, commit, undo y audit log.

Fase 4 — Display + dashboard

GC9A01, tarjetas de información, web de administración y OTA.

Fase 5 — Wake word

Activación local o servidor, VAD, barge-in y conversación continua.

Fase 6 — Hardware definitivo

PCB, caja 3D, fuente, acústica, montaje y botón/encoder de calidad.

Definición exacta del MVP

“¿A cuánto tengo diluido el Safraleine?”

El MVP está terminado cuando el usuario puede mantener presionado el botón, hacer esa pregunta y recibir una respuesta correcta por el parlante, tomada de una fuente de datos del laboratorio y no de memoria inventada.

Plan de pruebas

Audio

  • Ruido ambiente.
  • Distancia 30/60/100 cm.
  • Eco del propio parlante.
  • Interrupciones.
  • Ganancia.

Red

  • Wi‑Fi débil.
  • Corte de router.
  • Reconnect.
  • Chunks perdidos.
  • Reinicio de gateway.

Dominio

  • Dilución 1%, 10%, 50%.
  • Escalado 1 g → 25 g.
  • Material puro vs solución.
  • Undo.
  • Versionado.

Seguridad

  • Token inválido.
  • Rate limit.
  • Tool write sin confirmación.
  • Inyección en notas.
  • Secret scanning.
